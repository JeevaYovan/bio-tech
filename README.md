# Rathika Biotech Products

Static marketing + product catalog site for
[Rathika Biotech Products](https://rathika.in), a Coimbatore-based maker
of biodegradable tableware from banana fiber, sugarcane bagasse, and
rice husk.

```
19 routes prerendered to static HTML.
Initial JS gzip:  82 KB.   Initial CSS gzip:  10 KB.
Lighthouse mobile: Perf 99 / A11y 100 / BP 100 / SEO 100.
GitHub Pages, custom domain rathika.in. ₹0/month hosting.
```

## Stack

- **Angular 21** standalone components, signals, modern control flow
- **Tailwind v4** (required by `@klaro/ui`) + SCSS app-level styling
- **`@klaro/ui` 0.6** design system (private npm registry)
- **Static prerender** via `outputMode: 'static'` — every route rendered
  to HTML at build time, no SSR runtime
- **Deploys to GitHub Pages** at `rathika.in`

## Quick start

```bash
nvm use         # picks up .nvmrc (Node 20+ required)
npm ci          # uses ~/.npmrc auth for the @klaro registry
npm start       # dev server at http://localhost:4200
```

The first `npm ci` requires the `@klaro` private registry credential in
`~/.npmrc`. See [DEPLOY.md](DEPLOY.md) for setup.

## Production build

```bash
npm run build
```

Outputs static HTML for every route to `dist/rathika/browser/`. The
postbuild step:

- copies `index.html` to `404.html` (SPA fallback for GitHub Pages)
- writes `.nojekyll` (prevents Jekyll processing)
- writes `CNAME` (already in `public/`, mirrored for safety)
- generates `sitemap.xml` from the prerendered routes

## Local production preview

The build artefact is plain static HTML. Two ways to preview:

### Option 1 — `serve` (zero config)

```bash
npm run build
npm run serve:static
# Visit http://localhost:4200
```

### Option 2 — Docker / nginx (closer to GitHub Pages headers)

```bash
npm run build
docker compose up --build
# Visit http://localhost:8080
```

The Docker setup is for local QA only. The production deploy path is
GitHub Pages, not the container.

## Image processing

Raw product photos live in `inputs/` (gitignored — they're heavy
WhatsApp exports). The processor generates AVIF + WebP + JPEG triplets
at multiple widths under `public/assets/`:

```bash
npm run images
```

Processed assets are committed to the repo so builds reproduce without
source images. The mapping (source → destination + widths) lives in
[scripts/process-images.mjs](scripts/process-images.mjs).

## OG image

A single 1200×630 Open Graph image is generated by:

```bash
npm run og
```

It composites the haystack hero with the brand wordmark and is the
default `og:image` for every route.
